# 検証と違反種別

## VAL-01

L0はManifest構造・意味制約、ファイル/encoding、独立したMarkdown読込を検証する。L1はL0に加え全構造規則、番号、表示、ID、AST及び未対応申告を検証する（MUST）。エラーがあれば対象レベルを不合格とし、不完全な処理を合格としてはならない。原典との一致、未申告の意味欠落、法的有効性は保証しない。

| 違反種別（rule） | 対象 |
|---|---|
| BASIC-01/BASIC-02/BASIC-03/BASIC-04 | バージョン、入力バイト、未対応、拡張 |
| MAN-01/MAN-02/MAN-03 | Manifest形状、パス、所属順序 |
| MD-01/MD-02/MD-03 | 構造領域、本文保存、無所属本文 |
| HEAD-01/HEAD-02/HEAD-03/HEAD-04 | 見出し、分類、scope、削除 |
| NUM-01 | 番号字句・範囲 |
| DIR-01/DIR-02/DISP-01 | マーカー字句、対応/ネスト/非空、表示番号 |
| AST-01/AST-02 | AST形状・整合 |
| ID-01/ID-02 | IDの導出・安定性 |
| SRC-01 | 位置・原文保存 |
| REF-01 | L1で参照解決を必須にしない |

実装固有の診断code/message/severityとこのruleを区別する（MUST）。失敗ケースでは期待するruleの診断を最低1件含める（MUST）。回復方法と追加診断順は規範化しない。未閉鎖と不一致が連鎖してよい。同じ現象に複数規則が関係する場合もfixtureに明示されたruleを報告する。未知属性等の字句エラーを親子エラーだけに置き換えてはならない。IO不能・未対応versionは処理不能としてL0を合格にしない。

## VAL-02

このリポジトリのCIは仕様資料の自己整合検査であり、汎用のMarkdown→法令AST実装ではない。Schema検証、固定期待値の親子/ID/本文/位置の整合、サンプルの限定検査、リンク検査を行う。Markdown領域判定、全異常系診断、全入力での一意AST構築は将来のvalidatorと独立実装で検証する。CI成功を「全仕様適合済み」と表示してはならない（MUST NOT）。
