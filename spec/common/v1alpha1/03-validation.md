# 適合レベルと検査

## VAL-01 適合レベルの定義

| レベル | 検証対象 |
|---|---|
| L0 | ファイル形式、Manifest、Markdown構文 |
| L1 | 法令の階層、番号、項・号の意味構造 |
| L2 | 法令内の明示的参照とファイル間参照 |
| L3 | 原典との内容一致、改正履歴、施行時点 |
| L4 | 他法令との参照整合性 |

- L0・L1・L2は、一つの版パッケージを対象とする。規則は版パッケージの要件（v1alpha2）で定める。
- L2は将来の版で定める。本版では正式に合格を宣言できない。
- L3・L4の検査区分は[VAL-05](#val-05-l3の区分と主張)と[VAL-06](#val-06-l4の区分)で定める。

## VAL-02 独立した判定

- 各レベルは、独立して判定し、報告しなければならない（MUST）。
- 数字の大きいレベルの合格から、数字の小さいレベルの全部または一部の合格を推論してはならない（MUST NOT）。
- 複数のレベルへの適合を主張する場合は、それぞれを検査し、結果を示す。
- あるレベルの検査が、ほかのレベルの結果を入力に使う場合は、その要件に明記する。明記のない場合、ほかのレベルの不合格を理由に、そのレベルを不合格にしてはならない（MUST NOT）。

## VAL-03 判定の入力と対象の記録版

| レベル | 入力 |
|---|---|
| L0〜L2 | 一つの版パッケージ（`law.yaml`と、そこに列挙したMarkdown） |
| L3 | 一つのRecordの正本の記録版（履歴マニフェスト、版パッケージ、字体注記）。原典照合では、固定した原典資料も加える |
| L4 | 登録台帳の記録版と、照合する複数のRecordの履歴マニフェスト。必要に応じて版パッケージを加える |

- 判定の結果には、対象とした記録版（リポジトリ、正本のcommit等）を記録しなければならない（MUST）。
- どの記録版についての判定かを特定できない結果を、適合の主張に使ってはならない（MUST NOT）。

## VAL-04 結果の値

- 各レベル（L3・L4は各区分）の結果は、次のいずれかで報告しなければならない（MUST）。

  | 結果 | 意味 |
  |---|---|
  | 合格 | 対象を検査し、違反がなかった |
  | 不合格 | 違反があった |
  | 対象なし | 入力に、そのレベルの対象がない（例: 履歴だけの法令リポジトリのL0・L1） |
  | 未完了 | 検査に必要な入力を処理できなかった。または、検査の前提となる結果が得られなかった |

- 対象なし・未完了を、合格とみなしてはならない（MUST NOT）。
- 次の入力は、処理不能として未完了としなければならない（MUST）。不合格にしてはならない（MUST NOT）。
  - 読めない入力
  - 知らないschemaVersion（知らない種類、知っている種類の知らない版、`schemaVersion`がない・文字列でないもの）
  - 組み合わせて使える版の対応表（[CORE-05](01-overview.md)）にない組み合わせ

  処理不能を不合格にしないのは、検査器が、知らない版の正しいファイルを違反と判定できないためである。
- 処理不能の理由は、その種類の`schemaVersion`を定める規則（版パッケージのBASIC-01、HIST-01、GLYPH-01、REG-01、REBR-01）の診断（`class: error`）で示す。この診断は、結果を不合格にしない。
- 不完全な処理を、合格としてはならない（MUST NOT）。
- 警告、判定不能、保留は、不合格の診断と区別して報告する。警告だけでは不合格にしない。
- 各レベル（区分）の結果は、そのレベル（区分）の診断から、次の順に決める。

  | 診断 | 結果 |
  |---|---|
  | 違反（`class: error`）が1件以上（処理不能の理由の診断を除く） | 不合格 |
  | 違反がなく、判定不能（`undetermined`）が1件以上。または処理不能 | 未完了 |
  | 違反も判定不能もない（警告・保留だけ、または診断なし） | 合格 |

- 判定できても警告しか出さない検査の判定不能は、警告と同じく、結果を決めるときに数えない。本版で該当するのは、HIST-06の順序の検査だけである。新しい規則がこれに当たる場合は、その要件と本項の両方に書く。判定できれば違反を出し得る検査（TYPE-07、GLYPH-11、XREF-03、XREF-06、CHG-04等）の判定不能だけを数える。
- 保留は、法令上まだ定まっていないこと等を正しく記録している状態であり、結果を未完了にしない。件数を報告する。

## VAL-05 L3の区分と主張

L3を次の区分に分け、区分ごとに判定・報告する。

| 区分 | 検査の内容 | 本版での扱い |
|---|---|---|
| 履歴構造 | 履歴マニフェストの形式、revision_id、時点値、版の順序、成立根拠が参照する関係、版と版パッケージの配置、本文の状態、効力の終了 | 正式 |
| 根拠 | 確認済みの主張の出典と箇所、未確認・不明の理由、字体注記の形式と本文との対応 | 正式 |
| 原典照合 | 版の本文と、固定した原典資料との一致 | 予約（[SRCM-01](#srcm-01-l3の原典照合)） |

- 履歴構造の検査は、版パッケージがL1に合格していることを前提にしない。全版のL1の結果は、別の集計として報告する。
- 各区分の結果は、Recordにつき一つとし、Recordの記録版のすべての版にわたる診断から[VAL-04](#val-04-結果の値)の表で決める。版ごとの内訳は、対象の`revision`を付けた診断と、全版のL1の集計で示す。
- 根拠の検査は、出典の記載があることと、その形式を確かめる。出典の内容が判断を裏付けるかは機械で判定しない。L3の合格は、判断の正しさを保証しない。
- 区分を付けずに「L3合格」と主張してはならない（MUST NOT）。合格した区分を明示して主張する（例: 「L3（履歴構造・根拠）合格」）。すべての区分が正式化されるまで、この制限を続ける。

## VAL-06 L4の区分

| 区分 | 検査の内容 | 本版での扱い |
|---|---|---|
| 関係の解決 | 関係の起点・終点のRecordを登録台帳で解決できるか（[XREF-01](10-cross-record.md)） | 正式 |
| 関係の整合 | 全部改正後のRecordの`totallyRevises`が、旧Recordの全部改正の関係と対応するか（[XREF-02](10-cross-record.md)） | 正式 |
| 時点の整合 | 時点値の`sameAs`と参照先の時点が一致するか（[XREF-03](10-cross-record.md)）。同じ起点の関係の公布の時点が一致するか（[XREF-06](10-cross-record.md)） | 正式 |
| 表示の整合 | 版パッケージの`law.number`が、採用中の番号主張と一致するか（[XREF-05](10-cross-record.md)）。食い違いは警告だけで、不合格にしない | 正式 |
| 条項参照の解決 | 他法令の条項・版を指定した参照の解決（[XREF-04](10-cross-record.md)） | 予約 |

- Record間の参照の結果は、解決済み・未取得・不存在確認済みの三つで報告する。未取得は判定不能の一つであり、[VAL-04](#val-04-結果の値)の表で区分の結果を未完了にする。
- L4を不合格とするのは、矛盾がある場合と、不存在確認済みのRecordを確定した関係が参照している場合（[XREF-01](10-cross-record.md)）に限る。未取得は不合格にせず、件数と対象を報告する。

## VAL-07 規則と診断

- 要件IDを、診断の規則（rule）とする。各系列の規則が属するレベルと区分は、次のとおりである。

  | 系列 | レベル・区分 |
  |---|---|
  | BASIC、MAN | L0（一部の規則はL1。版パッケージの要件で定める） |
  | MD | L1 |
  | HEAD、NUM、DIR、DISP、AST、SRC、ID、REF、PARA、TABLE、PRE、TOC | L1 |
  | HIST、REV、TIME | L3履歴構造 |
  | TYPE、GLYPH | L3根拠 |
  | SRCM | L3原典照合（予約） |
  | XREF | L4 |
  | REG、RID | 登録台帳の検査（L4の入力の前提。適合レベルとは別に報告する） |
  | CHG | 変更検査（適合レベルとは別に報告する） |
  | FIXREF | 参照の解決（適合レベルとは別に報告する。他のRecordへの参照も含む） |
  | REB、REBR | 再構築報告の検査（適合レベルとは別に報告する） |
  | CORE、CHAR、VAL、CONF、VIEW | 個別の検査を持たない。違反は、それを具体化する規則で報告する |

- 要件の文のうち、入力のデータを機械で検査しない要求（原典と比べて確かめる要求、入力者の作業の手順、実装の挙動への要求）は、違反しても診断として報告されない。個別の検査を持たない系列の要件で、具体化する規則がないものも同じである。どの文がこれに当たるか（名宛人と確かめ方）は、[要件との対応表](../../../docs/coverage.md#要件の名宛人と確かめ方)（参考）に一覧にする。
- 実装固有の診断のcode・message・severityと、規則を区別しなければならない（MUST）。
- 診断には、規則と、規則を定める版のschemaVersionを示す。共通の要件（`spec/common/`）の規則は`common/<版>`（例: `common/v1alpha1`）とする。要件IDは版ごとに意味を持つためである。
- 共通の型の規則（TYPE、TIME）の違反は、その型を使うファイルの検査の結果として報告する。履歴マニフェスト・字体注記ではL3の区分（TIMEは履歴構造、TYPEは根拠）、登録台帳では登録台帳の検査、再構築報告では再構築報告の検査とする。
- 回復の方法と、追加の診断の順序は規範にしない。一つの現象に複数の規則が関係する場合や、違反が連鎖する場合がある。
- 未知の属性等の字句の違反を、親子関係の違反だけに置き換えてはならない（MUST NOT）。

## VAL-08 Unicodeの版

- Unicodeのデータ（文字の範囲・属性）に依存する規則は、参照するUnicodeの版を固定する。Unicodeの拡張や属性の変更による結果の変化を管理するためである。
- 本版の規則は、Unicode 15.1のデータを参照する。範囲の中の割り当てと文字の属性（正規分解の有無等）は、この版のデータで決める。
- 本版の規則が参照する範囲の境界（CJK互換漢字のブロックのU+F900〜U+FAFF・U+2F800〜U+2FA1F、異体字セレクタのU+FE00〜U+FE0F・U+E0100〜U+E01EF）は、Unicodeの版によって変わらない。範囲の中の割り当ては、将来の版で変わり得る。

## SRCM-01 L3の原典照合

- 版の本文と、固定した原典資料の一致を検査する区分として予約する。本版では正式化しない。
- 照合に使う原典資料の固定方法と、文字単位の比較規則を定めるまで、照合の結果を適合として主張してはならない（MUST NOT）。照合できない版は、判定不能として報告する。
- 字が原典どおりかの検査（字体注記が正しいか）は、この区分に属する。
