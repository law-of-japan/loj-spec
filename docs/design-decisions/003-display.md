# DDR-003 表示番号と意味番号

- 問題: 属性だけでは汎用Markdownで号番号が見えず、本文から推測すると不安定。
- 選択肢: 本文のみ／属性のみ／両者を検査。
- 判断基準: 原文保持、通常表示、番号不整合の検出。
- 採用: 属性を意味番号、本文先頭を表示番号として照合。第1項のみ表示省略可能。
- 理由: 非表示の第1項も意味的に存在し、GitHubでの本文表示も保つ。
- 制約: 細分の表示は十進に限定。いろは等を勝手に置換せず未対応申告する。
- 再検討: 字母・括弧・ローマ数字の明確な対応辞書と原典例を揃えた次版。

## 2026-11-09: v1alpha2での扱い

無番号の項を型付けした（[PARA-01](../../spec/v1alpha2/09-structures.md)）。原典に項番号がない項は`numbering=implicit`とし、表示番号を置かず、[DISP-01](../../spec/v1alpha2/05-directives.md)の検査を行わない。意味番号は属性で明示する、という本DDRの判断は変わらない。表示番号の枝番号には「ノ」も許す。いろは等の細分の表示は引き続き未対応である。詳細は[DDR-012](012-version-package-v1alpha2.md)。

## 2026-11-12: いろはと括弧付きの十進

細分の表示番号に、いろはと、全角の括弧で囲んだ十進を加えた（[DISP-01](../../spec/v1alpha2/05-directives.md)）。意味番号は属性で明示し、表示番号を正規化して照合する、という本DDRの判断は変わらない。いろはは47字の列の順で正規化する。ローマ数字と細分の枝番号は引き続き未対応である。詳細は[DDR-012](012-version-package-v1alpha2.md)。
