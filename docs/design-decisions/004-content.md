# DDR-004 複数段落と混在本文

- 問題: bodyとchildrenを別配列にすると、号の後に続く親本文の順序が失われる。
- 選択肢: 単一body／body+children／textとnodeの混在content。
- 判断基準: 本文・順序の復元、実装言語への非依存。
- 採用: 混在content、原文のtext、別のソースbundle。
- 理由: Markdownの段落と法令の項を分離し、複数段落や通常リストも保全する。
- 制約: 原文bytesを別途保持しなければ元ファイル全体は復元できない。
- 再検討: 図表・ルビ等を型付けする際にtextから構造化インラインへの互換写像を定義する。

## 2026-11-09: v1alpha2での扱い

項・号・細分の本文に、表（[TABLE-01〜03](../../spec/v1alpha2/09-structures.md)）を子のノードとして置けるようにした。混在contentの形はそのままで、Tableは本文の中の出現の順を保つ。項・号・細分の本文の中のGFMの表は違反とした。ルビ等の構造化したインラインは引き続き未対応である。詳細は[DDR-012](012-version-package-v1alpha2.md)。
