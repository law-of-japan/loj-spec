# DDR-009 初版の未対応構造

- 問題: 未対応内容を通常本文として受け入れると、完全な法令意味保存と誤認される。
- 選択肢: 常に受理／全面拒否／宣言を保持しL1を拒否。
- 判断基準: 移行途中の保存、偽陽性の防止、機械的な判定。
- 採用: unsupportedFeaturesをManifestに記録。L0は可能、L1は不合格。
- 理由: 原典を失わずに未対応部分を可視化できる。
- 制約: 未申告の意味欠落を自動判定できない。原典照合は将来L3。
- 再検討: 前文・字母細分等の型とテストを追加する際に申告から正式表現へ移行する。

## 2026-11-09: v1alpha2での扱い

前文・制定文・無番号の項・項の中の表を、申告から正式な表現へ移した（[BASIC-03](../../spec/v1alpha2/01-overview.md)）。未対応の構造を`unsupportedFeatures`で申告し、L1を不合格にする、という本DDRの判断は変わらない。公布文・署名と改正法の附則は、未対応ではなく、版パッケージに収録しないものとした。詳細は[DDR-012](012-version-package-v1alpha2.md)。

## 2026-11-13: 申告のない未対応の構造

- 問題: L1のBASIC-03の検査が、`unsupportedFeatures`の申告の有無だけを見るのか、申告すべき構造が申告されているかまで見るのかが、検査の章の表と本文とで一つに決まらなかった。申告のある入力で、DISP-01等のほかの規則の診断をL1の診断として出すかも明らかでなかった。空の`unsupportedFeatures`が「申告がある」に当たるかも決まらなかった（[law-of-japan/loj-spec#50](https://github.com/law-of-japan/loj-spec/issues/50)）。
- 選択肢: 申告のない、機械で認識できる未対応の構造にBASIC-03の診断を出す（MUST）／出してよい（MAY）／出さない（採用）。空の配列は、L0の違反とする（採用）／申告なしとみなす。
- 判断基準: L1の結果が変わるか、検査の規則が一つに決まるか、名宛人と確かめ方の整理（要件との対応表）と合うか。
- 採用: BASIC-03のL1の検査は、申告の有無だけを判定する。申告のない未対応の構造は、その構造を扱う規則（DISP-01、PARA-01等）の違反として現れる。申告のある入力のL1の結果はBASIC-03の診断で決まり、ほかの規則の診断は参考の集計（[DDR-012](012-version-package-v1alpha2.md)）としてだけ扱う。申告はほかの規則の違反を免除しない。`unsupportedFeatures`の値は、構造の箇所や種類と結び付けない。空の配列はschemaで拒否し、L0（MAN-01）の違反とする。
- 理由: 機械で認識できる未対応の構造（表にない細分の表示、細分の枝番号、数字で始まる番号のない第1項）は、申告がなくてもDISP-01等の違反になり、BASIC-03の診断を加えてもL1の結果は変わらない。「出す」には、「認識できる未対応の構造」を列挙する新しい規則が要り、その中身はDISP-01の違反のうち特定の字形のものを呼び直すことになる。打ち間違いと未対応の構造を字形だけで分けることもできない。「出してよい」は、期待結果に挙げていない診断を許すCONF-01の下で今もそうなっており、書いても振る舞いは一つに決まらない。申告の記録の義務の名宛人は入力者であり、漏れは原典照合で確かめるものと整理できる。空の配列を許すと、記録の意図があいまいなデータが残る。
- 制約: CONF-01は期待結果に挙げていない診断を許すので、申告のない入力にBASIC-03を出す実装を、固定ケースでは見つけられない（[要件との対応表](../coverage.md)）。値と構造を結び付けるには未対応の構造の列挙値が要り、本判断では扱わない。
- 再検討: 未対応の構造の種類を列挙値にするとき。
