# DDR-029 二つ以上の条をまとめた削除条

採用日: 2026-11-24。対象: [HEAD-01・HEAD-02・HEAD-04](../../spec/v1alpha2/04-headings.md)、[AST-01](../../spec/v1alpha2/06-semantic-model.md)、[ID-01・ID-02](../../spec/v1alpha2/07-identifiers.md)、[AMEND-02](../../spec/v1alpha2/09-structures.md#amend-02-改正内容の中身)、[TYPE-07](../../spec/common/v1alpha1/05-types.md)。[law-of-japan/loj-spec#153](https://github.com/law-of-japan/loj-spec/issues/153)による。DDR-005の制約（範囲削除の拒否）を一部解く。

## 範囲のラベルの削除条

- 問題: 昭和22〜24年頃の改正規定は、「第九十條及ヒ第九十一條　削除」「第七十三條乃至第七十六條　削除」「第四條から第七條まで削除」のように、二つ以上の条をまとめて削除条の形で掲げることが多い（[調査の記録](../survey-showa-amendments.md)、[law-of-japan/loj-spec#150](https://github.com/law-of-japan/loj-spec/issues/150)）。現行の法令の本則にも「第六十六条から第六十八条まで　削除」がある（所得税法施行令。[試行の記録](../trial-real-laws.md)）。HEAD-04は範囲をまとめた削除の表示を未対応としたので、一か所でもあると、その版パッケージはL1に適合しなかった。
- 選択肢:
  - 範囲のラベルを持つ一つの削除条とし、`number`を始めと終わりの番号を`:`で結んだ範囲の番号とする（採用）。
  - 条ごとの削除条に分ける（「第九十條」「第九十一條」の二つのArticle）。原典にない見出しを補うことになり、`display`が原文のラベルでなくなる。「乃至」「から…まで」では、範囲の中にどの条（枝番号の条を含む）があったかを推測しなければならない。
  - 始めの条の番号を`number`とし、終わりの番号を別のフィールドに持つ。IDが始めの条のIDと同じ形になり、範囲であることがIDから分からない。フィールドを一つ加えることになる。
  - 未対応のままとする（この時期の改正法の多くと、現行の法令の一部が、L1に適合しないままになる）。
- 判断基準: 原典にない字・条を補わないこと。範囲の中の条の実在を推測しないこと。`display`を原文のラベルに保つこと。番号の重複をL1で検出し続けること。改正内容と本則・附則で同じ規則を使えること。
- 採用:
  - 範囲のラベルは、始めの条、結ぶ語（`及び`、`及ヒ`、`乃至`、`から`…`まで`）、終わりの条を空白なしに続けたものとする。削除条のラベルとしてだけ使える。
  - 意味ASTは一つのArticle（`status: deleted`）とし、`number`は範囲の番号（例: `90:91`、`12-2:12-5`）、IDは`/article/90:91`とする。e-Govの法令XMLも、範囲の削除条を一つの`Article`とし、`Num="66:68"`のように始めと終わりを`:`で結ぶ（`第三百二条及び第三百三条`も`Num="302:303"`）。
  - `及び`・`及ヒ`も範囲とする。二つの条を「及び」で結ぶのは、間にほかの条のない二つの条を指す書き方であり、番号の重複の判定（HEAD-02）を範囲で一つにできる。結ぶ語は`number`に表さず、`display`に残す。
  - 始めの条は、番号の順で終わりの条より前とする。番号の順は、正規の番号の成分を先頭から比べ、枝番号の条を元の条の後に置く（`12` < `12-2` < `13`）。
  - 番号の一意性（HEAD-02）は、範囲に含まれるすべての番号で判定する。範囲の中の番号を持つ条や、重なる二つの範囲は、番号の重複である。
  - 本則・附則・改正内容のどのscopeにも、同じ規則で置ける。改正内容の中の削除条の後の空行（AMEND-02）も同じである。
  - Scopeの照合（TYPE-07）では、範囲のラベルの形の部分は範囲の番号に直して比べる。範囲の中の一つの条を指す部分は、番号では照合できないので判定不能とする。
- 理由:
  - 原典は、まとめた一つの見出しと一つの「削除」で掲げる。一つのノードにすれば、見出しの行・`display`・位置（SRC-01）が原典の一つの表示に対応する。
  - 範囲の番号は、範囲の中に実在した条を列挙しない。「乃至」「から…まで」の中の枝番号の条の有無は、改正前の法令を見ないと分からず、改正内容のscopeの中では判定できない。
  - `number`を一つのフィールドのまま範囲の番号にすれば、IDの導出（ID-01）、ASTのフィールドの集合（AST-01）を変えずに済む。`:`は正規の番号に使わない字なので、範囲の番号と正規の番号を取り違えない。
- 制約:
  - 範囲の中にどの条があったか（枝番号の条を含む）は、ASTからは分からない。範囲の削除条を、範囲の中の条ごとの削除として扱うかは、利用者の側の判断である。
  - 範囲の削除条のIDは、範囲の中の条のIDと違う。後の版で範囲の一部を書き直す（例: 一つの条を改めて置く）と、IDが変わる（ID-02）。
  - 三つ以上の条を列挙した削除の表示（「第一條、第三條及ヒ第五條　削除」）、削除した項・号は、未対応のままとする。調査で見つけた形は、すべて二つの条を結ぶものだった。
  - 結ぶ語を原典どおりに選んだか（「乃至」を「から…まで」と書いていないか）、条ごとの削除条をまとめて書いていないかは、L1では検出できない（原典照合）。
- 再検討: 三つ以上の条を列挙した削除の表示や、範囲の項・号の削除を型付けする要求が出たとき。範囲の中の条ごとの履歴を記録する要求が出たとき。
