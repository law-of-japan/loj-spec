# DDR-027 番号のない列挙（列記）

採用日: 2026-11-20。対象: [LIST-01・LIST-02](../../spec/v1alpha2/09-structures.md#list-01-列記)、[BASIC-03](../../spec/v1alpha2/01-overview.md)、[MD-03](../../spec/v1alpha2/03-markdown.md)、[DIR-01・DIR-02・DISP-01](../../spec/v1alpha2/05-directives.md)、[AST-01・SRC-01](../../spec/v1alpha2/06-semantic-model.md)、[ID-01](../../spec/v1alpha2/07-identifiers.md)、[AMEND-02・AMEND-03](../../spec/v1alpha2/09-structures.md#amend-02-改正内容の中身)。[law-of-japan/loj-spec#142](https://github.com/law-of-japan/loj-spec/issues/142)による。

## 号と別の構造とする

- 問題: 労働省設置法（昭和二十二年法律第九十七号）第三條は、「労働省に大臣官房及び左の五局を置く。」に続けて、五つの局の名称を、番号も記号もなく一行ずつ掲げる。号（`item`）は番号が必須で、表示番号の検査を受ける。表ではない。行に分けた項の本文として書くと、列挙という構造を本文に隠すことになり（BASIC-03）、行を指すIDもない。
- 選択肢:
  - 号と別の構造（列記）とし、`list`のマーカーで一つの行ごとに囲む（採用）。
  - 番号のない号とする（`item`に`numbering=implicit`のような属性を加える。号は「第○号」と引かれる番号の単位であり、表示番号の規則（DISP-01）と、号の番号から導くIDの意味が、番号のない行にまで広がる）。
  - 項の本文の行として許す（構造として型付けせず、行を指せない。旧本文の箇条書きと同じく、構造を本文に隠す）。
  - 列挙の全体を一つのマーカーで囲み、行を本文の改行で分ける（行ごとのIDがなく、行を本文の形から推測することになる）。
- 判断基準: 原典にない番号を本文に足さないこと。号と区別できること。一つの行を永続的なIDで指せること。e-Gov法令XMLとの対応が取れること。
- 採用:
  - 列記の一つの行を一つの`List`とする。`number`は同じ親の中の列記の順序（1から始まる連番）で、入力者が属性で明示する。表示番号は持たず、`display`は空文字列とする。
  - IDは`{親のID}/list/{number}`とする。内容は本文だけとする。
  - 親は項・号・細分・改正内容とする。改正内容では、AMEND-02の群に「列記」を加える。
- 理由:
  - 番号を属性に置くことで、本文に番号を足さずにIDを導ける。無番号の項の`number`（PARA-01）と同じ考え方であり、表・改正規定の`number`（同じ親の中の順序）とも同じ形である。
  - 号と別の種類にするので、号の表示番号の規則と引用の単位を変えない。e-Gov法令XMLも、番号のない列挙を号（`Item`）と別の`List`で表し、`List`は番号の属性を持たない。会計検査院法第十二条第二項、恩給法第八十四条が同じ使い方である。
  - 恩給法のように各行の頭に「一」（ひとつ）を置く列挙も、列記として書き、「一」を本文に残す。表示番号とみなさないので、すべての行が「一」でも番号の重複にならない。
- 制約:
  - 号と列記の区別は、原典を見た入力者の判断であり、L1では検査しない（原典照合）。本文の行の頭の字から推測しない。
  - 列記の行の順序はIDに入るので、列記の行を加える・削る改正で、後の行のIDが変わる。表の行の`key`（TABLE-02）のような同一性の主張は持たない。号・項の番号の繰上げと同じく、IDは版の中の位置を示す（ID-02）。
- 再検討: 列記の行の同一性を版をまたいで主張する要求が出たとき、列記を条項として引用する例が見つかったとき。

## 未対応とする範囲

- 問題: e-Govの`List`は、入れ子（`Sublist1`〜`Sublist3`）と、段に分けた列記（`ListSentence`の`Column`）を持てる。法令標準XMLスキーマ v3.0の`Paragraph`は、`Item`の後に`List`を置ける。号と列記が同じ親に並ぶと、引用の順序（第何号か）と列記の順序の関係を決める必要がある。
- 採用: 号・細分と列記を同じ親に置くこと、入れ子の列記、段に分けた列記は、本版では未対応とし、`unsupportedFeatures`に申告する。号・細分と列記の混在は機械で認識できるので、申告がなければLIST-02の違反とする（BASIC-03の考え方による）。入れ子の列記はマーカーの親の違反（DIR-02）として現れる。表・改正規定と列記は同じ親に並べてよい。
- 理由: #142の試料（労働省設置法第三條）と調べた実例は、号のない項に列記だけを置く形だった。混在・入れ子・段組みの実例を確かめずに型を決めると、後で意味を変えることになる。
- 制約: 段に分けた列記を、欄の間に空白を置いた一つの列記の本文として書く誤りは、L1では検出できない（原典照合）。
- 再検討: 混在・入れ子・段に分けた列記の実例を収録する必要が出たとき。
