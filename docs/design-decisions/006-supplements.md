# DDR-006 附則の識別子

- 問題: 複数の附則が第一条を持ち、表示「附則」だけでは区別できない。
- 選択肢: 出現順serial／ファイル名／Manifestの永続key。
- 判断基準: 挿入・並べ替え・分割への安定性。
- 採用: supplement/keyの独立scope。originalは慣例として推奨。
- 理由: 見出しから識別できない情報をManifestに明示できる。
- 制約: keyの選択と維持は編集者の責任。改正法番号や施行日を自動導出しない。
- 再検討: 改正・施行モデルを追加する際も既存keyの移行表を必須とする。

## 2026-11-09: v1alpha2での扱い

附則の見出しは、「附」と「則」の間に全角空白を0個以上置いたもの（「附　則」）を受け付け、附則のscopeの`display`は原文のラベルとした（[HEAD-03](../../spec/v1alpha2/04-headings.md)）。字間の有無から附則の種類を推論せず、種類はManifestのkeyで示す、という本DDRの判断は変わらない。改正法の附則は、被改正法令の版パッケージに含めない（[BASIC-03](../../spec/v1alpha2/01-overview.md)）。詳細は[DDR-012](012-version-package-v1alpha2.md)。
