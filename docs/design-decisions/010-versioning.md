# DDR-010 拡張・適合・ライセンス

- 問題: alpha、適合レベル、CI成功が同じ「対応済み」と解釈されやすい。
- 選択肢: 緩い未知属性受理／version別の閉じた仕様、単一合格／段階別判定。
- 判断基準: 他言語実装との相互運用、主張の正確性。
- 採用: schemaVersionを厳密に固定し未知意味拡張を拒否。L0/L1のみ正式。L2は参考。
- 理由: 同一versionで実装ごとに異なる意味を生まない。資料CIを実装認証と混同しない。
- 制約: 拡張には別versionが必要。固定fixtureだけで全入力への適合は証明できない。
- 再検討: 独立実装と移行戦略が整った段階でbeta互換性ポリシーを設ける。

ライセンスは隣接loj-validatorと同様にMITを選択。規範文書・Schema・補助コード・架空本文を
同一条件にして再実装を容易にする。法令本文の権利扱いや上流資料のライセンスは変更しない。

## 2026-11-07: 適合レベルの独立性

ユーザーが明示したL0〜L4の定義をVAL-01に採用。数字は検証対象の識別であり、累積保証の段階ではない。
旧CONF-02の「L1はL0及びL1」を撤回する。共通入力処理の実施と他レベルへの適合保証は別である。
既存ランナーのcase.levelに応じた個別実行を維持でき、ケースの入力・期待値やSchema/EBNFの変更は不要。
L0正例の意味AST要求は別問題としてIssue #1へ保留する。

## 2026-11-09: 次期仕様での扱い

- 版パッケージを`loj/v1alpha2`とし、v1alpha1を凍結した。互換は保証しない。alphaの間も、一度公開した版の意味は変えない（[CORE-04](../../spec/common/v1alpha1/01-overview.md)）。
- 版パッケージのほかに4種類のファイル（履歴マニフェスト、字体注記、登録台帳、再構築報告）を設け、種類ごとに独立に版を上げ、組み合わせの対応表を[規範仕様の入口](../../spec/README.md)で公開する（[DDR-022](022-spec-structure.md)）。
- L3の履歴構造・根拠と、L4の関係の解決・関係の整合・時点の整合を正式化した。L2、L3の原典照合、L4の条項参照は予約のままとする。結果は合格・不合格・対象なし・未完了の四つで報告する（[VAL-01〜07](../../spec/common/v1alpha1/03-validation.md)、[DDR-016](016-l3-l4.md)）。
- 各レベルの独立性（2026-11-07）は変わらない。betaの互換性の方針を設ける条件（独立実装と移行戦略）も変わらない。
