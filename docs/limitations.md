# 制限と検証の境界

正式: L0/L1の文法、意味木、番号/ID、原文保存契約。日本法令全体の表現を保証しない。
いろは/ローマ数字/括弧による細分、無番号の条・項、前文、制定文、構造化目次、
条のない本則、分類本文、附則内附属資料、複雑な改正指示・新旧対照表、削除項/号は未対応。
細分は10段、番号の各成分は1〜9999。枝番号の成分数に意味的上限は設けない。
欠番・非連番・逆順は許すが、同一識別子の重複は許さない。

附属資料は不透明Markdownであり、表・図・数式・ルビの内部意味は保証しない。
L2の参照、L3の原典・改正施行履歴、L4の法令横断整合は正式適合対象外。
原典の構造を申告せず本文へ隠すことを機械的に完全検出する手段はない。
unsupportedFeaturesを明示したデータはL1を拒否する。

CIは機械可読データ、正例の限定source trace、期待木の整合を検査する。
未知入力の全L1診断、実際のGitHub表示、XML往復、大規模性能、原典の法律上の正確さは検証しない。
一般のMarkdown意味をPython補助実装に委ねて仕様として固定しているわけではない。
正例で使われない文脈も規範を満たす必要があり、実装者はCommonMark自体のテストも実施する。

ソース保持は別チャネルの契約であり、意味AST JSON単体からファイル配置・構造マーカーを完全復元できない。
IDは番号とscopeの安定性を保証するが、改正を跨いだ法的同一性を保証しない。
公開前に運用者によるalphaレビューが望ましいが、これを本作業の未完了承認条件にはしていない。
