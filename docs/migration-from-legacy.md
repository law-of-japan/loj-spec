# 既存Markdownからの移行設計

[既存規約](https://github.com/law-of-japan/loj-repository-management-guideline/blob/27eaa01db778aac04349eadab0942da3f8800a44/CONTRIBUTING.md)との比較。
本作業では実法令の移行や変換ツールを実装しない。

2026年11月7日の文字保存方針採用だけを理由に既存データを一括逆変換しない。新字体から原典の文字は一意に復元できない場合があるため、移行には原典との再照合を要する。具体的な移行手順と適用範囲は別途定める。

| 旧形式 | 新形式・確認事項 |
|---|---|
| 日付・種別・番号を含むリポジトリ名 | law.idへ継承可能。名称からメタデータを推測して確定しない |
| 章等をファイル名/ディレクトリで表す | Manifestの所属・順序と明示した分類見出しへ移す |
| 各ファイルの法令名H1、引用の分類経路 | law.titleと完全な分類見出しへ。本文引用と識別して除去 |
| 項のordered list | number属性を持つparagraph。表示されない第一項も作る |
| 号のunordered list | item。元の表示文字列を保持 |
| 制定附則、改正附則リンク | original等の安定キー。リンクだけなら全文収録と主張しない |
| 別表専用ファイル | appendix/key。不透明保存はセル構造の移行ではない |
| 改正ブランチ・施行前ブランチ、改正単位commit | 運用は別管理。schemaVersionで施行時点を代用しない |
| 旧字体・字点等の置換方針 | 本仕様は自動文字変換禁止。既存の置換履歴と原典との差を記録 |

手順: 元commit・全ファイルhash・出典を保管する。原典を確認して条/項/号の境界を列挙し、
通常リストとの違いを人が判断する。項番号がMarkdown表示で自動補正されていないか確認する。
旧形式の構造用インデントと箇条書き記号だけを取り除き、本文の文字・句読点・改行の変更を別差分にする。
Manifestを作り、分類の省略情報をディレクトリと原典から補い、条ごとにIDを割り当てる。
ファイル分割は条間に限定し、附則を識別可能なscopeへ分ける。

例えば旧`1. 本文`とその配下の`- 一　号`を、それぞれparagraph number=1とitem number=1で囲む。
通常のリストには変換を適用しない。いろは細分、番号なし構造、改正指示、附則内別表など
変換不能なものはunsupportedFeaturesへ申告し、元ファイルを保存してL1完全適合としない。

移行前の人手確認済み意味表（scope、条番号、親子、本文）と新ASTを比較する。
番号とIDの対応表を作り、条数・項数・号数・順序・本文差分を確認する。
原典から変更された文字は理由・出典位置を別途レビューする。リンク書換えは本文の編集と区別して記録する。
改正履歴全体の自動再構成や新旧同一条の同定はL3以降の課題である。
